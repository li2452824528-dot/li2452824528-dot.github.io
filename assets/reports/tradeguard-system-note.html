AI assistance with a human decision boundary.

TradeGuard is an independent system-design project for transaction-risk investigation. It explores how agents can organize signals and evidence while consequential actions remain controlled, reviewable, and auditable.

Context
Synthetic transaction-risk environment
Role
Independent designer and developer
Scope
Architecture and local application stack

The design question

The central question was not how to automate every decision. It was how to use AI assistance to make an investigation more structured without allowing an unreviewed system output to trigger a consequential action.

This led to a deliberately bounded design: the system can collect signals, organize a case, and surface supporting evidence; authorization remains a human responsibility.

Control flow

The workflow separates analysis from execution and records the path between them.

System boundary

Agent assistance: aggregate signals, retrieve relevant knowledge, and assemble investigation context.

Human control: review the case before authorizing any consequential action.

Auditability: preserve the case history and decision trail so that actions can be reviewed later.

Public scope

This note describes the project at an architectural level. It does not publish source code, internal implementation details, credentials, datasets, or any claim of deployment on real enterprise transactions.

The project's value is the design choice: favoring traceability and controlled escalation over unrestricted automation in a synthetic environment.
